# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

**Солонка** (Solonka, репозиторий `denprog5/solonka`, до 1.0 называлась ShitCounter) — счётчик русского мата для стримов на Windows (Rust, один exe). Слушает выбранный микрофон, офлайн распознаёт речь моделью GigaAM v2 (через `sherpa-onnx`), увеличивает счётчик на каждое матерное слово и пишет число в текстовый файл, который показывает OBS. Живёт в трее. Пользовательская документация — `README.md`.

Главное нефункциональное требование: приложение работает параллельно с игрой и OBS и **не должно влиять на FPS**. Любое решение, добавляющее постоянную нагрузку на CPU/GPU/RAM, лишние потоки, таймеры или опрос, требует обоснования. Минимализм важнее фич. Второе по важности — точность счёта. Поддерживается только русский язык.

## Команды

```bash
cargo build --release          # exe в target/release (~19 МБ, sherpa-onnx/onnxruntime слинкованы статически)
cargo test                     # unit-тесты (матчер, дата, auth OBS, разбор релиза)
cargo test matcher             # тесты, в имени которых есть "matcher"
cargo clippy --all-targets -- -D warnings
cargo fmt
powershell -ExecutionPolicy Bypass -File scripts/fetch-model.ps1 [-Dest target/debug]   # модель в <exe>/models/gigaam-v2-ru
target/debug/solonka.exe --wav file.wav   # прогон WAV через VAD → GigaAM → матчер: текст, счёт, % от реального времени
VOCAB=words.txt cargo test vocab_scan -- --ignored --nocapture   # матчер по списку слов (по одному на строку)
powershell -ExecutionPolicy Bypass -File scripts/build-installer.ps1   # release + модель + Inno Setup → dist/Solonka-Setup-<в>.exe и Solonka-Update-<в>.exe
```

Первая сборка: build-скрипт `sherpa-onnx-sys` сам скачивает статические библиотеки sherpa-onnx.

Сборка и дистрибуция:
- `.cargo/config.toml` включает `+crt-static`: sherpa-onnx собрана с `/MT`, без этого линковщик ругается на конфликт CRT (LNK4098), а exe зависит от VC++ Redistributable. Не убирайте.
- `build.rs` через `embed-resource` встраивает `assets/app.rc` (иконка `assets/icon.ico` и иконки трея `tray-*.ico` с ID 2–4 + сведения о версии). Иконки трея грузятся из ресурсов (`icon.rs`), Windows сама выбирает кадр под DPI. При смене версии в `Cargo.toml` обновите и `VERSIONINFO` в `app.rc` (build-installer.ps1 проверяет совпадение). Картинки (`docs/logo.png`, `docs/banner.png`, иконки) сделаны генератором Codex; мелкие кадры иконок (16–32) — упрощённая солонка без символов.
- Установщик — `installer/Solonka.iss` (Inno Setup 6, ставится в `%LOCALAPPDATA%\Programs` без админа). Из него собираются два: полный (модель внутри) и `/DUpdateOnly` — без модели (~7 МБ), который ставится только поверх существующей установки и его качает автообновление. Тихое обновление не трогает автозапуск (`Check: not WizardSilent`), а с `/RELAUNCH=1` перезапускает программу. Миграция с 0.1: удаляются `shit-counter.exe` и старые ярлыки, значение Run `ShitCounter` переносится в `Solonka`. `AppId` не менять — по нему работают обновление поверх и удаление. Перед копированием файлов и при удалении запущенный экземпляр убивается через `taskkill` (Restart Manager трей-приложение не закрывает). `.iss` и `.ps1` хранятся в UTF-8 **с BOM**, иначе Inno Setup / Windows PowerShell 5 портят кириллицу.
- Проверка установщика: `setup.exe /VERYSILENT /SUPPRESSMSGBOXES /DIR=<папка> /TASKS=autostart`, затем `unins000.exe /VERYSILENT` — тихое удаление сохраняет `%APPDATA%\Solonka`.

Режим `--wav` использует тот же `Pipeline`, что и живой микрофон (вывод виден только в debug-сборке — в release нет консоли). Тестовую речь удобно делать через `System.Speech` (голос «Microsoft Irina Desktop», 48 кГц), но синтезатор коверкает «ё» и «уи» — финальная проверка точности только на живом голосе (у пользователя есть `sound.wav` в корне: 20 с непрерывного мата, GigaAM находит 36). После правок матчера прогоняйте `vocab_scan` по большому словарю русских слов и смотрите на ложные срабатывания.

Модель (`model.int8.onnx` 226 МБ + `tokens.txt`) должна лежать в `models\gigaam-v2-ru\` **рядом с exe** (или путь в `model_path`); в репозиторий не коммитится.

## Архитектура

Четыре потока, связь между ними — только через общие `Arc<Mutex<…>>` и уведомления главному потоку:

- **Главный поток** (`main.rs`) — голый Win32-цикл `GetMessageW` для `tray-icon`/`muda` (без winit). Владеет `cpal::Stream` (он `!Send`) и конфигом. Метод `App::update()` идемпотентно приводит всё к желаемому состоянию: запускает/останавливает захват (пишем, только если `listening` и модель загружена), обновляет пункты меню, иконку и подсказку.
- **Аудио-колбэк cpal** (`audio.rs`) — только downmix в моно f32 и `push` в lock-free кольцо `rtrb` (5 с — запас на время распознавания длинной фразы). Поток распознавания будится `unpark()` примерно раз в 100 мс, а не на каждый колбэк. Никаких аллокаций и логики в колбэке.
- **Поток распознавания** (`recognizer.rs`, приоритет LOWEST) — кадры по 10 мс на родной частоте устройства → энергетический VAD (адаптивный уровень шума, предзапись 300 мс, «хвост» 500 мс) собирает фразу. Тишина в модель не подаётся — это основная экономия CPU. Когда фраза закрыта, она ресемплится в 16 кГц (`LinearResampler` из sherpa-onnx) и распознаётся целиком (`OfflineRecognizer`, NeMo CTC, **1 поток** — 2 потока быстрее, но суммарно едят больше CPU). Фраза длиннее 10 с режется в самом тихом 10-мс окне последних 1,5 с, чтобы не разрубить слово. Без звука поток спит в `park_timeout(30s)` — это же тик проверки смены суток.
- **Поток OBS** (`obs.rs`) — клиент obs-websocket v5 на синхронном `tungstenite`, нужен только в режиме `stream`; в остальных режимах спит в `park()`. Подписка только на категорию Outputs; при `StreamStateChanged` с `OBS_WEBSOCKET_OUTPUT_STARTED` счётчик сбрасывается. Без OBS пробует подключиться раз в 5 с: подключение к закрытому локальному порту ничего не стоит, а короткий интервал не даёт пропустить старт стрима.
- **Поток обновлений** (`update.rs`) — HTTPS через системный WinHTTP (без TLS-крейтов): `releases/latest` через 15 с после старта и раз в 6 ч, остальное время спит. Найденное при запуске ставится само (если `auto_update` и рядом с exe есть `unins000.exe`), найденное позже — только пункт меню, чтобы не перезапускаться посреди стрима. SHA-256 файла сверяется с `digest` из API GitHub. Установщик запускается с `/VERYSILENT /RELAUNCH=1`, программа выходит по `EV_QUIT`. Ассеты релиза должны называться `Solonka-Setup-*.exe` / `Solonka-Update-*.exe`.

Неочевидные места:

- **Почему GigaAM, а не Vosk.** Проект начинался на `vosk-model-small-ru`, но её словарь закрытый: из 356 частых форм мата там нет 213 (похуист, охуевший, спиздить, съебался, уебать…), и Vosk подменяет их похожими словами («заебало» → «за и балла»). GigaAM пишет по буквам (33 буквы без «ё»), поэтому выдаёт любую форму. На TTS-тесте с редкими формами: GigaAM 18/20, Vosk 14/20; на живом голосе GigaAM правильно распознаёт то, что Vosk теряет. Ложных срабатываний ноль у обоих. Не возвращайтесь к словарным моделям.
- **Ошибки GigaAM фонетические** («похурист», «выубываться»): если на живом голосе какая-то форма систематически пишется «на слух», расширяйте правила матчера под это написание (с тестами на похожие обычные слова), а не меняйте модель.
- **Уведомления главному потоку** (`win.rs`): `notify_main(EV_*)` ставит бит в атомарный `PENDING` и шлёт `PostThreadMessageW` как «будильник». Пока открыто меню трея, модальный цикл Windows выбрасывает thread-сообщения — флаг при этом не теряется. Не заменяйте это на чистые thread-сообщения.
- **Пути к модели** передаются как 8.3 short path: sherpa-onnx открывает файлы через `char*`, кириллица в пути ломает загрузку.
- **Матчер** (`matcher.rs`) — чистая функция с тестами. Корни `ху[йеяюи]` и `еб` матчатся только в начале слова после явного списка приставок, иначе ловятся «тихую», «страхуем», «хлеб», «себя». Остальные правила: подстроки (`пизд`, `залуп`, `гандон`…), начала слов (`бля`, `пидор`…), точные формы (`сука`, `манда`… — «команда», «мандат» не должны считаться) и исключения (`бляха`, `бляшка`, `ебонит`). Раздельное «на хуй» считается один раз (по слову «хуй»). При изменении правил добавляйте в тесты и мат, и похожие обычные слова.
- **Счётчик** (`counter.rs`) пишет `count.txt` атомарно (temp + rename, с повтором — OBS может держать файл открытым) и `state.json` только при изменении. При переключении в режим `daily` день начинается с текущего момента, а не сбрасывается сразу. Сутки начинаются в `day_start_hour`.
- **Ошибки захвата**: при пропаже устройства — одна автоматическая попытка перезапуска, повторная ошибка в течение 10 с «замораживает» захват до действия пользователя (`capture_suspended`), чтобы не крутиться в цикле.
- Процесс: `BELOW_NORMAL_PRIORITY_CLASS` + EcoQoS (`eco_mode`), один экземпляр через именованный мьютекс, `windows_subsystem = "windows"` только в release.
- **OBS**: если `obs_url` по умолчанию, порт и пароль читаются из `%APPDATA%\obs-studio\plugin_config\obs-websocket\config.json`; оттуда же понятно, выключен ли WebSocket-сервер. Строка OBS в меню показывается только в режиме `stream`.
- **Автозапуск** — значение `Solonka` в `HKCU\…\Run`, переключается из меню; состояние галочки читается из реестра при каждом `update()`.
- **Открыть настройки**: у `.json` часто нет программы, и `ShellExecute` молча запускает невидимый OpenWith — поэтому сначала `AssocQueryString`, иначе Блокнот.

Файлы пользователя: `%APPDATA%\Solonka\` (при первом запуске переносится из `%APPDATA%\ShitCounter`) — `config.json` (правится руками; ошибка разбора не перетирает файл), `state.json`, `count.txt`.

## Замеры (Ryzen 7 7800X3D, release)

- в тишине: ~0,1% одного ядра; память ~285 МБ рабочего набора / ~265 МБ private;
- во время речи: распознавание ~9–12% от длительности речи на одном ядре;
- загрузка модели ~0,6 с.

## Релиз

1. Поднять версию в `Cargo.toml` и `assets/app.rc`, `cargo test`, `cargo clippy --all-targets -- -D warnings`.
2. `scripts/build-installer.ps1` → два файла в `dist/`.
3. `git tag vX.Y.Z && git push --tags`, `gh release create vX.Y.Z dist/Solonka-Setup-X.Y.Z.exe dist/Solonka-Update-X.Y.Z.exe`. Тег без `v` тоже понимается, но держим `v`.
